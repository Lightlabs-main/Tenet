# Tenet on Devnet

Everything on Devnet is a **real transaction moving real token balances**, with
test assets that have **no monetary value**:

| Mainnet                   | Devnet (this build)                                              |
|---------------------------|------------------------------------------------------------------|
| Circle USDC               | **TUSDC** — "Tenet Devnet USDC — no monetary value", faucet-minted |
| Pyth `PriceUpdateV2`      | **PriceFeed** accounts — devnet pricing simulation, operator-set  |
| Jupiter                   | **Market** — fixed-price inventory swaps with a 0.30% spread      |
| Tokenized stocks / PreStocks | **DEVNET TEST INSTRUMENTS** — not real stocks or securities    |

## Two programs

| Program | Address | Role |
|---|---|---|
| `tenet` | `7pLYmJXsTJW7vWuT9BwYqNCWUDXp8SR1JKmKYNofAECf` | The product: Mandates, Circles, epochs, execution window, NAV, exit, fork. Identical on every network. |
| `tenet-devnet` | `6ZXVyvYPPLhoMTF4BDa2M3SLpWRvHxPCLjD9WFQzBdNm` | Devnet-only venue: TUSDC faucet, price feeds, markets. Never deployed to mainnet. |

The core program does not know about `tenet-devnet`. Its `Config` (decision
A-23) names the network, the **only** execution venue, and the **only**
program whose price accounts it will read — and `initialize_config` fails
closed on anything else:

- **Mainnet** must use canonical USDC, Jupiter, the Pyth receiver and ≤ 60 s price age.
- **Devnet** must **not** use canonical USDC — so test prices and the test
  venue can never value or move real money.

A single price adapter (`programs/tenet/src/price.rs`) turns either source into
Pyth's `Price` struct, and the NAV snapshot, price-impact floor and
target-weight check all run the same code on both.

### Known limitation

A funding window whose valuation snapshot times out (~150 slots, ~60 s,
between opening and finalizing) can only be cancelled; contributors are
refunded, holdings, execution and exits are unaffected, but the deployed
program cannot open further windows for that Circle. The app keeps a
NAV-priced settlement to 4 wallet approvals (2 for a first window) and can
resume a stalled valuation, so this is unlikely; the fix needs a Circle
state change and is planned post-hackathon.

### What the program enforces during Execute

`begin_execution → venue buy → end_execution` in one transaction:

- only the configured venue may run inside the window (instructions sysvar);
- the executor is a delegate on the Circle's USDC vault for at most `max_in`, revoked at the end;
- real vault deltas: spent ≤ max_in, received ≥ min_out;
- received ≥ fair value × (1 − Mandate price-impact limit);
- vault ≤ Mandate supply-consumption cap of the live mint supply;
- post-trade asset value ≤ its Mandate **target** share of NAV — targets were
  proven against the per-asset, pre-IPO, issuer and company caps at finalize,
  so this enforces all of them.

Any failure reverts every token movement.

## Operator commands

Run from the repo root on a machine holding the deployer keypair **file**
(`TENET_DEVNET_KEYPAIR`, default `~/.config/solana/tenet-devnet-deployer.json`).
Keys are read from that file only; never paste a private key anywhere.

```bash
anchor build
anchor deploy --provider.cluster devnet     # tenet + tenet-devnet
pnpm devnet:setup     # idempotent: faucet, Config, 6 instruments, feeds, markets, registry
pnpm devnet:price TNVDA 110 --underlying 112   # move a test price
pnpm devnet:price TSPACEX 40 --mark 50         # market vs mark −20%
pnpm devnet:reset     # prices, spreads and inventory back to the catalog
pnpm devnet:e2e       # the whole product with 4 fresh wallets, verified from chain
pnpm devnet:status    # read-only health check (no keypair needed)
pnpm devnet:metadata  # wallet name + logo for the instruments and TUSDC (idempotent)
```

**Upkeep on the operator host** (`scripts/devnet-cron.sh`, installed in cron):
`status` daily at 06:00 UTC and `refresh` (republish every price unchanged, so
feeds never pass the program's 30-day freshness limit) Mondays at 06:30 UTC,
logged to `/var/log/tenet-devnet.log`.

**Pyth.** The web app reads live Pyth data through Tenet's proxy
(`/api/pyth` → `services/solana-rpc-proxy`): a fixed server-side allowlist of
feeds, the API key read from a root-only systemd `EnvironmentFile`
(`/etc/tenet/pyth.env`) and never sent to the browser. `pnpm devnet:pyth-relay`
(cron, every 2 minutes) publishes each fresh Pyth price (≤ 60 s, confidence ≤
1% — the program's own mainnet rules) into the TTSLA / TVOO devnet feeds;
while the US market is closed it relays nothing and the feed keeps its last
Pyth price. This is an operator relay of Pyth data, not Pyth's on-chain
verification, which the program performs on mainnet.

**Wallet metadata.** Every instrument and TUSDC carries Metaplex Token
Metadata (Fungible) pointing at `https://tenetstocks.website/tokens/<SYMBOL>.json`,
so wallets show e.g. "SpaceX Pre-IPO Devnet Test" with a DEVNET TEST logo.
TUSDC's mint authority is the faucet PDA, so its metadata is created by
`tenet-devnet::set_tusdc_metadata` (operator only; the faucet PDA signs and is
the update authority — no keypair controls TUSDC). Tested against the real
Metaplex program: `TENET_MPL_SO=<dump> cargo test -p tenet-program-tests --test devnet_metadata`.

Every script checks the RPC's **genesis hash** and refuses anything but
Devnet. `devnet:setup` records all addresses in
`packages/sdk/src/devnet/deployment.json`; the web app reads that file.

Rent at the size-optimised build (`opt-level = "z"`): tenet.so 756 KB,
tenet_devnet.so 332 KB — about 5.6 SOL locked, ~7.7 SOL at the deploy peak.

## Demo video script (≈ 5 minutes)

Prep: wallet (Phantom/Solflare/Backpack) switched to **Devnet** with ~0.5 free
Devnet SOL. Two wallets make the exit/no-dilution point clearer.

1. **Landing → Open Devnet workspace.** "Collective investing, governed by rules."
2. **Create your Circle.** Click **Get 1,000 TUSDC** (faucet, signed by you).
   Keep the Frontier Technology defaults (5 assets, pre-IPO cap 30%, 2-minute
   window). **Create Mandate & Circle** — a few wallet approvals.
3. **POOL.** The guided demo card shows step 2. *Add money* → contribute 500.
   Show "contribution pending" and **Cancel & refund** exists. (Optionally a
   second wallet contributes 300.)
4. Wait for the 2-minute window → **Close window & set shares**, then
   **Issue shares & complete window**. Overview shows your position.
5. **EXECUTE.** *Portfolio* → **Execute epoch · 5 buys**. Open a transaction in
   the explorer: begin → market buy → end. Try a manual **Buy** again: the
   program refuses — target reached.
6. **VALUE.** *Prices & value*: NAV, weight vs target, TSPACEX market vs mark
   −20%, TNVDA token vs underlying −1.96%, supply held, compliance ✓. Labelled
   DEVNET TEST DATA. (Operator: `pnpm devnet:price TNVDA 110` and refresh —
   NAV and drift move.)
7. **EXIT.** *Exit* → 25% → **Exit 25% to my wallet**. Your wallet now holds
   TNVDA, TAAPL, … and TUSDC; the others' share of every asset is unchanged.
8. **FORK.** *Fork rules* → pre-IPO cap 30 → 15, halve the pre-IPO targets →
   **Fork & create the new Circle**. The new Circle opens; *Overview → Fork
   lineage* shows parent → fork. Fund it and execute: TSPACEX stops at 7.5%.
9. **Explore** lists every Circle, with "Fork of …".
